# 提示词 + 轮盘合并架构设计

> Loom slug: `merge-architecture` | Kind: product | Phase 1 交付物

## 结论

"合并"=**消灭独立的"轮盘配置页"，pinned 变成提示词的内联属性；轮盘运行时窗口保留，但它只是提示词集合的投射视图，不是被管理的对象。** 导航 5→4：`提示词`（pin/编辑/预览一体）、`模板库`、`记录`、`设置`。数据模型不变（`prompts.pinned` 已存在，`db.rs:42-59`），"轮盘条目"降级为筛选 `WHERE pinned=1`。顺带修复隐式耦合：ID1 热键依赖主窗口选中态（`find_prompt_for_context` 忽略上下文只读 `selected_prompt`，`db.rs:401-414`），改为显式"默认快捷提示词"或"最近使用 #1"。

## 1. "合并到底是什么意思"——三种理解逐一判定

| 理解 | 描述 | 判定 |
|---|---|---|
| A. 两个页面合成一个页面 | 提示词页里嵌一块轮盘预览区 | ❌ 只搬家具不改心智，轮盘仍然是个"东西" |
| B. pin 内联化 | 消灭轮盘页；每条提示词卡片上有"加入轮盘"开关 | ✅ 部分采纳——这是合并的核心 |
| C. 统一视图 | 提示词是唯一数据源，轮盘=它的 pinned 子集视图 | ✅ 采纳为心智模型 |

**推荐 = B+C**：信息架构上不再有"轮盘"这个一级对象；运行时 wheel 窗口照旧存在（它是全局浮层，物理上必须是独立窗口——`src/main.rs` 里 `show_wheel_window` 的独立窗口定位是正确的），但用户心智里它只是"我的提示词里标了⭐的那几个，按热键出现在手边"。

类比：收藏夹不是"另一个浏览器功能"，是书签的一个属性。轮盘同理——**pin 是属性，轮盘是渲染**。

## 2. 合并后信息架构

```mermaid
主导航（4 项，侧边栏）
├── 提示词 Prompts          ← 合并后唯一内容页
│   ├── 顶部：搜索框（Fuse 模糊 + 前缀快进）＋ 标签筛选 ＋ 视图切换
│   ├── 列表/卡片：每条 = 名称/摘要/标签/⭐pin/使用数 ⋯菜单(编辑/复制/删除)
│   ├── 详情/编辑抽屉：内容、变量、标签、app_scopes、pin 开关、版本
│   └── "轮盘预览"按钮：直接触发一次真实轮盘弹出（所见即所得）
├── 模板库 Library          ← 原市场页改造（见 MARKET_DECISION.md）
│   └── 内置精选 / URL 导入 / 文件导入 / 导出我的提示词
├── 记录 Log                ← 原日志页，保留但重新定位
│   └── 使用记录 + 注入策略/耗时/成功率（修完统计 bug 后才有意义）
└── 设置 Settings           ← 通用/热键/注入策略/外观(明暗+语言)/数据/关于
```

**被消灭的页面**：`wheel-panel`（`src/index.html:99-109` 整个"轮盘管理"页）删除；其唯一真实职责（pin 管理）内联进提示词列表。"适应规则"卡片从未实现（`wheel-panel` 里是一张写死的演示卡），一并删除不留尸骨。

**导航项判定**："日志"页保留但改名"记录"。理由：PHASE0 团队靠它抓到两个真实 bug（`PHASE0_EXECUTIVE_SUMMARY.md` §5.1），重度用户也需要"哪个提示词最常用"的反馈；但它不再是主路径，放导航末位。

## 3. 提示词页内部结构（合并的核心界面）

```
┌─────────────────────────────────────────────────────┐
│  🔍 搜索提示词…  ⌘K        [标签▾] [排序: 最近使用▾]  │
├──────────────┬──────────────────────────────────────┤
│ ⭐ 轮盘(4)    │  全部提示词 (23)                      │
│ ──────────  │  ┌────────────────────────────────┐   │
│ ▸ 润色      │  │ ⭐ 代码审查         dev · 用42次 │   │
│ ▸ 翻译      │  │ ⭐ 英文邮件润色     写作 · 用38次│   │
│ ▸ 会议纪要  │  │    会议纪要模板     会议 · 用15次│   │
│ ▸ +加项     │  │    ...                         │   │
│             │  └────────────────────────────────┘   │
│ 标签云       │                                        │
│ #写作 #dev   │                                        │
└──────────────┴──────────────────────────────────────┘
```

要点：
- 左栏"⭐ 轮盘"区 = pinned 子集的**只读镜像**+ 排序调整入口；点 ▸ 展开可拖拽排序（非必需功能，见 §4）
- 右栏是全量列表；每条卡片 ⭐ 图标的开/关就是"加入/移出轮盘"——一行代码的语义，零独立页面
- "轮盘预览"直接调 `trigger_show_wheel`（IPC 已有）——预览即真实弹出，不做假预览组件
- 空态："暂无提示词 → 去模板库导入 / 新建第一条"，消灭空白页困惑

## 4. 功能必要性评级（围绕合并形态）

判定标准（用户钦定）："没有它会死吗？"+ AI 重度用户的真实日工作流：*找得快（搜索/排序）→ 选得准（预览/变量）→ 注得稳（注入）→ 留得住（备份）*。

| 候选功能 | 评级 | 一句话理由 |
|---|---|---|
| **pin 内联化（⭐）** | 必需 | 合并的本体 |
| **最近使用排序 / 使用频率** | 必需 | `usage_logs` 表已存在（`db.rs:211`），轮盘默认序=frecency 是重度用户最自然的序；零新增数据模型 |
| **轮盘内打字过滤** | 必需 | 轮盘弹出后直接敲字过滤（selector.js 的 Fuse 能力平移进轮盘），一举突破 6 格限制并**消灭 selector 死代码的复活理由** |
| **显式"默认快捷提示词"** | 必需 | 修复 `find_prompt_for_context` 的隐式耦合——当前 ID1 热键注入的是"你上次在主窗口点开过的那条"，用户根本无法预测 |
| **导入/导出 JSON** | 必需 | 模板库的前提，也是用户数据主权的底线 |
| **变量填充 {{var}}** | 有价值·可延后 | 字段已备好（`variables_json`, `db.rs:53`），但需要一个注入前表单流程，Phase 2 中期做；先支持 `{{clipboard}}`/`{{date}}` 两个自动变量（零 UI 成本） |
| **轮盘内 "+ 快速新建"** | 有价值·可延后 | 中心按钮长按/右键出"新建"，减少"先回主窗口"的往返 |
| **pin 拖拽排序** | 有价值·可延后 | inject_order 字段已有（`db.rs:55`），UI 可先按使用频率自动排，手动拖拽是锦上添花 |
| **快速试运行（不粘贴只看渲染）** | 有价值·可延后 | 详情页"预览"按钮渲染变量后的成品文本，不碰目标窗口 |
| 提示词版本对比 | 不做（本期） | `version` 字段计数已有但无人需要 diff 视图；真需要时再加 |
| 模板继承/嵌套 | 不做 | 复杂度极高收益极低， espanso 的 extends 已被证明是少数派功能 |
| 多轮盘/场景轮盘 | 不做 | 一个轮盘+过滤已覆盖 95% 场景；多套轮盘 = 多套心智 |
| 应用自动匹配规则 | 不做（本期保留数据） | `app_scopes_json`/`context_rules` 字段保留（`config/mod.rs:25-26` 已有入口），但"按窗口自动选提示词"的推荐排序可延后到数据积累后 |
| 云同步 | 不做 | North_Star 边界："云同步需显式开启"，本期不做 |
| 团队协作/分享 | 不做 | 见 MARKET_DECISION.md |

**搜索结果**的既有职责不变：提示词页搜索框继续用 Fuse（`main_simple.js:207-208` 权重 name 0.6/tags 0.25/content 0.15），加 `/` `⌘K` `Ctrl+F` 前缀快进与 `content:"..."` 强制全文——详见 UI_UX_REDESIGN.md §7。

## 5. 需要后端配合的最小改动清单（Phase 2）

1. `get_top_prompts_paginated` → 改为 `ORDER BY frecency`（`usage_logs` 聚合 + pinned 优先），现有"最近使用"是把字符串日期当数字算（`db.rs:359-360` 的 `strftime('%s', last_used_at) as u64` 排序已正确，但 `usage_count` 永远 +1 不论成败——配合 INJECTION_RESEARCH §7 一起修）
2. ID1 热键语义：新增 `default_prompt_mode: "last_used" | "fixed"` 设置项 + `default_prompt_id`
3. 新增 IPC：`SHOW_WHEEL` 已存在；轮盘内过滤纯前端完成（全量 prompts 一次给轮盘窗口，数据量 <1MB 无压力）
4. `selected_prompt` 表：迁移为 `default_prompt` 或废弃（数据迁移见 Phase 2）

## 6. 风险与取舍

- **风险**：pin 内联后"轮盘长什么样"对新手不可见 → 用"轮盘预览"按钮 + 设置页示意图解决
- **取舍**：不做"按应用自动切换轮盘内容"（app_scopes 自动过滤）。理由：`find_prompt_for_context` 的上下文参数目前根本没被用（`db.rs:401-414`），说明该需求真实强度未被验证；先把排序做好，自动匹配等有数据再议。
