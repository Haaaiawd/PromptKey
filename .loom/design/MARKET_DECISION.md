# 市场机制决策报告

> Loom slug: `market-decision` | Kind: product | Phase 1 交付物

## 结论

**做，但不做"市场"——做"模板库"。** 本版本落地 = 内置精选提示词包（本地 JSON，一键导入）+ 自定义源导入（粘贴 URL / 选本地文件）。**砍掉社区分享形态**（要后端、审核、账号、版权处理，与"本地优先、隐私"北极星直接冲突，成本远超收益）。UI 上 `market-panel` 改名"模板库"，空壳按钮替换为真实功能；同时补齐"导出/导入 JSON"这一比市场更基础的能力。预计后端工作量 ≈ 零（复用现有 prompts 表与 create_prompt），全部成本在前端与内容策展。

## 2. 四个方向的成本/风险评估

| 方向 | 实现成本 | 维护成本 | 法律/版权风险 | 与北极星兼容性 | 判定 |
|---|---|---|---|---|---|
| **A. 内置精选库** | 低：一个 JSON + 导入按钮，复用 `create_prompt` | 低：版本升级时更新包内 JSON | 低（自写或明确授权来源，需 owner 策展把关） | ✅ 完全兼容（零网络） | **做** |
| **B. 社区分享** | 极高：后端、账号、上传、审核、举报、分页 API | 极高：持续运营，日活不够就是鬼城 | 高：用户上传内容的版权与内容安全责任 | ❌ 冲突（云端、隐私、体积） | **不做** |
| **C. URL/自建源导入** | 低-中：`fetch(URL)` 拉 JSON/YAML + 预览导入 | 低：无服务端 | 中：内容由用户自选来源，产品侧加"来源自担"提示即可 | ⚠️ 兼容但需显式用户动作（符合"云同步需显式开启"精神：拉取是用户主动行为） | **做**（作为 A 的扩展形态） |
| **D. 文件/剪贴板导入导出** | 低：`tauri-plugin-dialog`/`fs` 已在依赖里（`Cargo.toml:41-42`） | 低 | 无 | ✅ | **做**（归并入模板库页，不算市场） |

### 参照系

- **espanso hub**（同类工具的最接近答案）：git 仓库托管的 package 源 + 本地安装，无自建后端。证明"本地优先 + 社区内容"的正确形态是**用户自选源**，不是应用内商城。
- Raycast Store / Text Blaze Community：都需要平台运营投入，对一个单人维护的本地工具是错配。

## 3. 推荐形态（最小可行）

**名称**：导航项"市场"→"**模板库 / Library**"（"市场"一词暗示交易与社区，名不副实会误导）。

**数据格式**（与导出格式统一，一份格式两用）：
```json
{
  "format": "promptkey-pack",
  "version": 1,
  "pack": { "name": "写作助手精选", "author": "PromptKey", "lang": "zh" },
  "prompts": [
    { "name": "...", "content": "...", "tags": ["写作"], "app_scopes": [] }
  ]
}
```

**三个来源入口**（同一"预览 → 选择 → 导入"流程）：
1. **内置精选包**：随安装包打包（Tauri `bundle.resources`），中英各一套分类模板（写作/编程/翻译/邮件/分析，各 4-6 条）。解决新用户"空列表"的最差首体验——这是它真正的价值，不是"市场"。
2. **URL 导入**：设置/模板库页粘贴 JSON URL（GitHub raw、gist、自建）。拉取前明示"将从该地址获取数据"。不做自动刷新、不做订阅同步。
3. **本地文件/剪贴板导入**：`.json` 文件选择或粘贴文本导入；同时提供"导出我的提示词"按钮。

**UI 形态**：模板库页 = 来源切换（内置/链接/文件）+ 卡片网格（名称/摘要/标签/条数）+ 逐条勾选或"全部导入"。导入即拷贝进 `prompts` 表，**不保留源关联**（不做"已安装包管理"——那是 espanso hub 的复杂度，我们不需要）。

**不做的事**：不做评分、评论、排行榜、更新检查、包卸载、依赖版本。这些都是"市场"复杂度，不回答"没有它会死吗"。

## 4. 版权与审核

- 内置包：由 owner 策展自写或标注来源（建议收录时统一改写为自有表述，避免直接搬运第三方商业库）。
- URL 源：导入对话框固定提示"内容由来源方负责，请确认来源可信"。
- 无后端即无审核义务，这是砍掉 B 的核心理由之一。

## 5. 对 UI/UX 设计的影响

- 导航从 5 项变 4 项（合并后：`提示词`、`模板库`、`记录`、`设置`——详见 MERGE_ARCHITECTURE.md）。
- market-panel 的骨架可直接改造为模板库页，工作量极小。
